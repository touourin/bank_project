# 银行合成数据

两张 CSV 用于开发交接，均为虚构客户和事件。默认快照日期为 **2026-09-17**，随机种子为 **20260917**，客户数为 **20**。
数据不复制原始 Excel 的客户号、账号、企业名称或交易内容。

| 文件 | 内容 |
| --- | --- |
| `CCM_C_CUST_FLAG_INFO.csv` | 155 列，每个客户一份标签快照 |
| `E_CRM_C_CUST_TOUR_EVT_SUM.csv` | 8 列，每行一个事件，客户编号关联标签表 |
| [字段说明.xlsx](字段说明.xlsx) | Excel 字段字典：155 个标签字段、8 个旅程字段、事件码对照和 117 项事件属性 |
| [FIELDS.md](FIELDS.md) | 同一份字段说明的 Markdown 查阅版，可在 IDE 或 GitHub 中查看 |
| `manifest.json` | 参数、记录数、事件覆盖、校验和与待银行确认清单 |
| [schema.json](../../configs/bank/schema.json) | 源字段与 mock 约定的唯一配置 |

## 使用

在项目根目录运行：

```bash
make mock
make mock-check

# 也可以使用 Python 3.9+，无需安装项目或第三方包
python3 scripts/generate_mock.py --customers 20 --as-of 2026-09-17 --seed 20260917
python3 scripts/validate_mock.py

# 大批量数据输出到已被 Git 忽略的 data/，不覆盖交接样例
python3 scripts/generate_mock.py --customers 100 --output-dir data/mock
python3 scripts/validate_mock.py --input-dir data/mock
```

相同 schema、参数和脚本版本生成相同的文件字节。重新生成只替换两张 CSV 和 `manifest.json`。
字段说明是当前样例的文档快照；`make mock` 不自动更新 Excel 和 Markdown 文档。字段定义或模拟规则变化后，需同步更新这两份说明。
调整 schema 或手工修改 CSV 后，应重新生成并校验；校验器会检测文件与 manifest 不一致。
独立脚本不启动 FastAPI、不调用 LLM、不向 Neo4j 写数据，业务接口仍为框架占位。

## 格式

- UTF-8 **带 BOM**（`utf-8-sig`）、逗号分隔、LF 换行。BOM 用于 Excel 直接打开时识别中文编码。文件第一行是列名，CSV 引号和 JSON 引号由标准 CSV 写入器转义。
- 程序读取 CSV 时使用 `encoding="utf-8-sig"`，避免把 BOM 读入第一个列名；项目读取器已处理。已经用错误编码打开的 Excel 窗口需要重新打开修正后的文件，添加 BOM 不会刷新现有窗口。
- 标签列名及大小写沿用 `CCM_C_CUST_FLAG_INFO` 结构页。旅程使用结构页的大写列名 `DT,ROWKEY,EVT_CLASS,EVT_TYPE,CUST_ID,OCCUR_DT,KEY_FLAG,PROPERTIES`，而非样例页的小写表头。
- `PROPERTIES` 是 CSV 单元格内的 JSON 对象文本。两层解析：先读 CSV，再解析该列 JSON。
- 编号、账号、码值按字符串读取。账号带前导 `0`；Excel 中应通过“从文本/CSV”导入并将标识符列指定为文本，避免自动数值转换。
- 日期是 `YYYYMMDD` 字符串，包括源表允许 10 字符的日期字段。
- SQL `DECIMAL(26,8)` 在 CSV 中写为普通十进制文本、固定 8 位小数。脚本使用 `Decimal`；JSON 金额写为数值字面量，读取示例：`json.loads(text, parse_float=Decimal)`。
- CSV 空单元格表示未提供值；JSON 中的 `""` 表示显式空字符串，未出现的键表示未提供该属性。原始 Excel 未明确的属性必填性不由校验器擅自补齐。
- `schema.json` 是这两个离线工具使用的字段契约配置，含 SQL 类型与 mock 约定，不是标准 JSON Schema 或 FastAPI 的 `openapi.json`。

## 已确认的处理

1. `客户旅程.CUST_ID = 客户标签.cust_ind`。客户建档事件的 `PROPERTIES.客户号` 也使用同一值；`ecif_cust_id` 单独保留。
2. `YWJC0017`、`YWJC0018` 分别显示为“未定义1”“未定义2”，只沿用签约日期、经办机构这两个样例属性，不对应到外汇代客或国内证业务。
3. 账户开立的 `账户类型` 保留空字符串；复合授信申报的 `授信品种` 为非必填，本版省略该键。
4. 企业舆情统一使用 `舆情属性`，视原样例 `舆论属性` 为同一字段。
5. 贷款还款未结清保留 `授信品种`，已结清保留 `贷款品种`，不合并两个字段。
6. 代发工资签约保留样例里的 `账号`，未采用尚未确认的改名建议；合成账号不附带原样例中的填充空格。
7. 代缴税费签约的 `经办机构` 沿用空字符串。其他未确认字段也不因为需求要求展示就变成必填。

三个临时事件码不是银行编码，长度均满足 `EVT_TYPE VARCHAR(20)`。`YWJC0017/0018` 继续单独生成“未定义1/2”，没有与临时事件建立映射。正式码和字段表示确认后，更新 `schema.json`、生成/校验规则及相应测试，再重新生成数据；不要直接批量替换未知事件码。

默认 20 客户生成 **280 条旅程，覆盖 31 个事件码**，其中这次补充 48 条。少于 5 个客户时只覆盖相应场景，实际覆盖见 manifest。
字典中的 `YWJC0007` 授信年检没有属性定义或样例，不在本次 5 项搁置需求中，仍未生成，见 `excluded_event_codes`。

## 本版模拟约定与边界

这些是生成测试数据的约定，不代表银行正式码表或业务计算规则。

- 金额均按 **CNY 元**生成；无币种列的金额也按此解释。比例用 **0～1**，例如 `0.5` 表示 50%。
- 一位字符的标志统一使用 `0/1`。未提供码表的行业、机构、企业分类、生命周期等使用 `MOCK` 前缀取值。标识符不用于真实开户、证件或统一社会信用代码有效性测试。
- 每五个客户轮换存款理财、授信未结清、授信已结清、授信拒绝、其他业务场景。销户事件关闭另一个已开户的次要账户，主账户继续存在。当前模拟全部客户仍存续。
- 发生日期不晚于快照日期；到期日可以晚于快照日期。首次建档、开户、签约、申报、批复、放款、还款按顺序构造，外部事件也在需求的展示时间窗口内。
- 本版每个客户最多一笔已批复授信、一笔贷款。贷款余额 = 放款 − 还款；已用额度按该贷款余额生成，可用额度 = 批复额度 − 已用额度。贷款为 CNY，无其他授信占用。
- 工商注册为每个客户生成一条；本版注册日期等于标签成立日期，统一社会信用代码和注册资本与标签相同，资本按 CNY 元。注册日期可以早于建档日期。
- 授信通过客户各生成一份合同，签约发生在批复通过与放款之间，合同金额等于本版批复额度；到期日与贷款到期日相同。`MOCK_ACTIVE` 表示模拟有效状态，贷款结清不自动解释为授信合同失效。
- 存款理财场景客户生成上市事件，`ipo_ind` 为 `1`，其他客户为 `0`。`MOCK_MAIN_BOARD` 表示模拟主板，`MOCK_STOCK_*` 为测试证券标识，不是真实证券代码；其他板块标志保持 `0`。外汇签约分配给存款理财/其他业务场景，国内证签约分配给授信通过客户；未据此推断“外汇企业客户”等标签的银行统计口径。
- 存款余额为本版活期与定期存款之和；平均余额为独立模拟指标，不声称可以从完整日流水重算。当前不提供完整交易流水、所有历史事件或财报表。
- 代发金额来自两次代发事件；假设两批为同一组员工。`agt_cnt_12m` 按两批人数合计，`agt_num_12m` 为这组员工人数；笔均金额、当月金额、月份数、最近代发日期据此生成。采用这一约定是为了让 mock 自洽，正式统计口径仍以数据方定义为准。
- `snd_bl_cust_sign_ind`、`pyrl_sign_dt` 的字段名与中文日期含义待确认，保留源列名且留空。不会据此重命名源字段或构造可能错位的日期。
- 第一份需求里的 22 项年报/财报指标位于另一张财报结构，本次两张源表 mock 不扩充为第三张财报表。分行/支行层级映射也未加入。

## 校验范围

`make mock-check` 检查表头、源字段长度/数值精度/日期格式、主键重复、客户关联、建档内外编号、事件码范围、事件大类、合法 JSON、已出现属性的类型，以及上述 mock 场景的金额和签约标志一致性。补充场景还检查工商注册与标签对应、上市标志、合同金额与签约顺序，以及待确认清单的实际覆盖数量。
它校验本版合成数据，不将样例推断成银行完整业务校验标准。

源字段参考《上海银行数据表结构参考.xlsx》的 `CCM_C_CUST_FLAG_INFO`、`E_CRM_C_CUST_TOUR_EVT_SUM` 和 `客户旅程数据样例`。源业务展示需求参考《营销助手数据需求.xlsx》的 `客户标签`、`客户旅程`。原始工作簿不随项目分发，生成脚本不依赖它们。
