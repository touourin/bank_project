# 五表可用性修正版

数据均为虚构测试数据。当前主目录保留五张导入表：

| 文件 | 行数 | 列数 | 每行含义 |
| --- | ---: | ---: | --- |
| 客户标签.xlsx | 1,000 | 155 | 客户快照 |
| 客户旅程.xlsx | 16,700 | 8 | 客户事件 |
| 征信.xlsx | 1,110 | 52 | 主体的一份征信报告 |
| 工商.xlsx | 1,002 | 49 | 企业快照 |
| 交易流水.xlsx | 539,534 | 103 | 账户交易 |

征信、工商各有“数据”和“字段说明”两页；第1行是字段名，导入时勾选“跳过说明页”。字段说明包含类型、单位、来源表列及归并规则。汇总是静态导入数据，原明细变化后需要重新生成。

完整原明细保存在 `来源明细/征信明细.xlsx`（98张来源表、21,619条记录）和 `来源明细/工商明细.xlsx`（39张来源表、8,324条记录）。各来源表及字段说明保持原文件字节不变；主文件的 source_refs 指向原 Sheet 与 source_row。做账户、股东或交易关系图时仍应使用明细，不把汇总行当成明细。

征信按“主体类型＋报告编号”汇总，企业与个人分别保留；工商按“统一社会信用代码＋数据日期”汇总。两者各精确关联1,000个客户，未关联的主体保留空客户编号。先分别汇总账户、股东等一对多明细，再关联主体，避免行数和金额倍增。

征信中100份报告存在财务版本冲突，相关汇总金额留空并标注；11份报告的担保币种缺失，相应人民币合计为空。未明确单位的金额保持原表单位，不假定为元。工商主表资本已是元，不重复换算；股东及对外投资SUBCONAM从万元转为元。未知、缺失、不适用不当成0。

客户标签、旅程、流水全量检查后保留原结构和值。当前值相同不代表业务含义相同：法定代表人与实际控制人、交易日期与起息日期、账户金额与对手方金额不强行合并。详见 [五表整理说明](../../docs/five-table-summary.md)。

交易流水完整 Excel 是本地大文件，不随 Git 仓库分发；生成器、字段规则和校验脚本随代码提交，重建前需准备已核对的源字典 schema，见 `docs/source-mock.md`。上面的行数描述本地完整项目数据集。桌面版旅程/流水为16,678/757,830行，本次分别处理两套数据，没有相互覆盖。

银行未提供的码表采用说明页中逐字段定义的测试码。客户旅程中的MOCK_FX_SIGN、MOCK_LC_SIGN、MOCK_CREDIT_SIGN为测试事件，正式银行事件码仍需映射；技术编号的MOCK_前缀在项目版保持原关联。证件和账号按文本保存。标签与源数据包expected/customer_tags.csv一致；早先的日均、状态、余额和风险样例修订未被本次结构整理重写。

本次已全量回读新汇总的字段、值、类型，核对借贷余额、股东出资和原始明细哈希；其他三表主键无缺失/重复，旅程属性全部为有效JSON对象。银行原始字典没有改动。远程 shanghai_proj 已同步桌面最终版征信/工商，并全量核验其余三表；两张表的字段目录也已更新。项目版与桌面版是独立数据集，本目录不是远程库的逐值镜像。前端已导入批次保留历史快照，重新接入源库可读取新结构。最新工作簿元数据以manifest.json中的subject_summary_revision为准，source_table_layout_revision描述保留的来源明细。
