# 消歧修复与同集回归结果

2026-09-21。数据集 `graphrag_entity_disambiguation.jsonl`，200 条样本、487 个提及、14 类；模型始终为 `dashscope/qwen3.7-plus`。原文、金标和评分分母保持不变，未决与失败均计为未命中。

| 提及准确率 | 249/487，51.13% | **433/487，88.91%** |

准确率提高 **37.78 个百分点**，原来的正确提及全部保留，另外修正 184 个提及。纯名称/别名首匹配基线为 86.04%；该基线利用了题库候选顺序偏置。

同名异实体由 13/40 提高到 40/40，多实体混合由 14/50 提高到 50/50，缩写歧义由 8/30 提高到 25/30。完整分类结果及全部剩余错误见实验报告。

本数据已用于错误分析与开发，因此这是**同集回归**，不是独立测试集泛化准确率。测试范围为给定提及和候选目录的消歧，不包括 GraphRAG 抽取与检索召回，也不能直接当作生产图谱自动合并准确率。

## 生产代码变化

1. **明确提及位置。** `Mention.source_span` 使用 Unicode 字符偏移、左闭右开；验证范围和字面名称。引用必须覆盖该处提及，不能只引用全文中另一处同名实体。局部窗口保留明确别名桥梁，避免把“北岚即北岚研究所”截成不足以引用的片段。
2. **原文证据地址。** 模型选择原文片段 ID，应用回填原始子串并执行已有引用校验。不存在、跨侧或错位 ID 被拒绝；原文过短时直接保留未决。未放宽逐字校验。
3. **目录与来源分流。** 显式 `evidence_kind=catalog` 才允许目录词义匹配。普通 GraphRAG/DB 节点始终是 `source`；两个来源的合并继续要求身份依据，不能只凭同名及同类业务描述。
4. **全候选竞争。** 对有明确位置且拥有多个目录候选的提及，一次比较全部候选。仅选中项返回同一建议，未选中项保留未决；全部不匹配才可返回 NIL。等价、不可区分的候选不按顺序猜选。
5. **调用与缓存。** 同一提及的竞争请求共享一次模型调用和预算；候选集合取实际比较边的双向并集，覆盖非对称 top-k。超时取消共享底层请求，避免游离请求突破并发限制。缓存绑定提示词、版本、全部输入与候选内容，旧策略结果不会混用。
6. **图谱接入。** 聚合前导出与图谱适配传递上游明确提供的 `source_span`。重复同名没有位置时不猜首处；合并多个不同位置时不伪造单一坐标。DB 仍使用原结构化字段证据。默认新字段在序列化时省略，旧 corpus 哈希保持兼容。

修改主要位于 `resolution/engine/{contracts,evidence,catalog,model_judge,resolver}.py`、`resolution/{service,adapter}.py`、原始记录导出与图适配。评测脚本只负责输入转换和计分，判定逻辑位于生产引擎。

## 保留的限制

- 30 个“上下文依赖”提及缺少足以选择词义的上下文；公司/品牌类的 15 个品牌提及被金标归到公司，与当前身份策略冲突；另有“演唱会→北京”的错标。全部仍纳入主成绩。
- 按开发前独立审计固定的 46 个问题提及做敏感性分析，剩余成绩为 431/441，97.73%；这不是主成绩，也不是重新标注后的官方分数。
- 引用 ID 证明文本出处，不能机械证明语义身份。全候选模式未选中项为 `uncertain`，所以其两两负例指标与旧版不同，应比较提及准确率和覆盖率。
- 新增位置能力依赖上游提供可靠位置，已有聚合节点不能凭空恢复各次提及。目录匹配策略不会自动用于普通图节点。
