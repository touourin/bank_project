# 消歧策略优化与实测

2026-09-21，数据集 `a-4bf79a21b54b`（原项目企业方案），145 个节点、167 条边。

## 已实现

- 新的在线任务默认使用 `retrieval_policy=balanced`、每节点最多 10 个候选。保留 `original` 原始宽召回，可在页面切换，原命令行配置默认仍是原策略。
- 名称、已有别名、身份编号和人工约束优先。精筛不会把描述里出现共同词直接当作身份线索；仅有描述线索时，需要多个低频词及一定名称相似度。向量召回仍可接入。
- 不兼容的已知实体类型抑制弱匹配。同名、明确别名、共享编号、人工约束仍可跨类型核验；未知类型、DB 自定义类型与本体 ID 不用于排除候选。
- 模型预算优先分配给身份线索较强的候选。名称或编号一致本身不会触发无条件合并；原身份验证、全簇冲突检查、人工审核与撤销规则保留。
- 改为固定数量的持续工作协程，不再等待一批中最慢的请求完成才启动下一批。消歧任务内复用 HTTP 连接池，保持原并发、超时及重试上限。
- 有效模型结果按原文、模型和提示词缓存。优化提示词只要求短、连续、逐字原文引用，不放宽原文验证；原提示词产生且已通过验证的缓存可复用。
- 分析中每约 2 秒更新进度，提供估算剩余时间、失败/预算跳过计数，以及最多 50 条已返回候选的只读预览。首条结果立即保存。最终结果保存全部候选，完成后开放审核。
- 页面可筛选“建议同一实体”“判为不同实体”“证据不足”“失败或预算未覆盖”。失败原因区分原文引用不支持、JSON/格式错误、输出截断、超时等，不保存或展示供应商敏感错误信息。

## 质量验证与边界

- 原项目合成金标样例：候选从 29 对降到 9 对，4 对已标注同一实体全部召回。该小样例不代表真实业务总体召回率。
- 回归覆盖跨类型别名、DB 未知类型、源数据不变、高置信线索优先预算、慢请求隔离、并发预算上限、缓存复用、引用失败禁止合并、分析中只读预览和完成后审核。
- 真实业务尚无完整人工金标，精筛召回率未测量。未被召回不代表已确认不同；可切换宽召回、提供人工审校词表或向量、人工指定节点。
- 仍有8 对引用未通过验证，不能算作模型有效结论。模型建议同一实体也需要按所选策略审核，不等同于准确性保证。

## 年份、期间、会议序号与产品型号修正

此前名称相似度容易把只差年份、次数、型号前缀的记录排在前面。相似度只是召回依据；旧页面对不同实体和模型失败的候选也显示合并箭头，造成“已经判为相同”的误解。现在候选仅并列展示；只有人工确认合并后才显示多个节点到一个节点的过程。

- 在规则、模型和缓存调用之前检查名称中的身份限定。不同年份、会议届次/次数、董事会/监事会职责、报告期间、观测时点、产品型号冲突时，判为不同实体并阻止合并。A100/H100 保留字母前缀。
- 年份名称缺少月份或期间时，判为证据不足并自动不合并；不把“2025年”擅自补成“2025年末”，不凭相同金额或模型生成描述补全身份。补全来源身份信息并重新分析后，才可能解除这一限制。
- 支持中文/阿拉伯会议序号、中文年份、全角型号、明确日期与月末的规范化；报告期间与观测时点分别记录，避免把半年期间和6月末直接视为相互矛盾。
- 公司、人物等实体不根据描述中出现的年份拆分。该规则不覆盖所有自然语言时间表达，也不以未发现冲突作为同一实体证明。
- API 合并入口检查整个已有合并组和历史来源记录，阻止用一个缺少年份的节点间接连接不同年份。GraphRAG 和数据库图谱共用这一检查。
- 历史模型原判决不改写；读取候选时追加当前身份限定、有效判定与冲突明细。既有人工决定不会被自动撤销。

修正后的真实实验 `c4a4e707-b024-4839-a0ea-99d8abf29bcb`：314 对候选中，104 对明确身份冲突，102 对身份限定不完整；剩余108 对进入模型判断（103 次缓存命中、5 次实际请求）。本轮耗时3.69秒，最终195 对不同、107 对证据不足（含5 对引用校验失败）、12 对同一实体建议。原始145节点/167关系逐项一致，没有执行合并。此耗时依赖已有缓存。

验证：327项后端测试通过、17项条件测试跳过；6项相关浏览器测试通过。用户截图的6组不同案例全部覆盖，另覆盖数字格式等价、公司/人物不因描述年份拆分、人工与传递合并拦截、撤销、历史建议展示、缺失期间不合并以及旧审核提示更新。

## 明确冲突不再进入人工审核队列

身份字段明确冲突或身份限定不完整的候选使用 `excluded` 状态，页面显示“自动不合并”，独立统计 `excluded_count`，默认待核验列表不再显示。这些结果没有合并、再次保留或撤销审核按钮，也不提示“请核验”；可在分析记录中通过状态筛选查看身份差异与来源。API 同样拒绝将这些结果重置为待审核或人工合并。其余结果的展示规则见下节。

该策略同时适用于新任务和历史记录读取。历史模型依据、人工操作记录、修订号和图谱数据不被读取操作改写；已有人工决定不自动撤销。仅名称/金额相似并不能证明同一实体，`identity-dimensions-v2` 将缺少年份、月份、观测时点等限定的情况也移出待审核队列。

两类不合并保留不同的依据：明确冲突的判定仍是 `different`；期间未对齐的判定仍是 `uncertain`，展示“身份依据不足，暂不合并”，不冒充已证实不同。旧版本“需人工决定”的系统提示在当前展示中被替换，历史模型原判决保留在证据字段中。

真实记录 `c36ae871-2124-45d6-bc49-6058da6fca94` 在身份规则更新后读取验证：314对结果中206对自动不合并（104对明确冲突、102对限定未对齐），当时剩余108对待核验，后续按下节规则继续筛选。“2025年应收账款 / 2025年9月末应收账款”现在为 `excluded + uncertain`。145个节点及167条关系与原图逐项相同，修订号仍为0、无合并与人工操作记录；此次更新未重跑模型。

## 先由模型判断，仅确认有效合并建议

此前已使用大模型，但将判为不同、证据不足和调用失败的结果也列成“待审核”，造成用户需要逐条排除无效候选的问题。现在默认页为“合并建议”，只有 `origin=model`、模型建议 `same`、两侧原文引用有效且身份限定未阻断的结果才进入 `pending` 队列。分析中的最多50条预览也优先选择模型合并建议，并在任务完成前锁定确认按钮。

其他结果使用 `not_recommended` 状态，独立统计 `not_recommended_count`，移至“分析记录”，没有合并或逐条保留按钮。没有模型配置时，不会把名称相似度包装为模型建议；界面提示配置模型后重新分析。已有审核结果与撤销操作保留，人工指定节点仍是明确发起的独立功能；身份限定检查继续阻止不安全合并。

真实任务 `91ca7ce7-421f-4692-92d7-4b8add5df134` 使用 `dashscope/qwen3.7-plus`。314对结果中206对被身份限定规则排除，108对模型比较包含103条已验证缓存与5次本轮调用；其中12对建议同一实体、91对判为不同、5对调用结果未通过验证。新规则读取后为 **12对待确认、206对自动不合并、96对未建议合并**。读取历史结果即可生效，无需重新运行模型；原判决、引用和人工审计不改写。

验证覆盖模型同一/不同/不确定结果分流、无模型与引用失败不生成建议、确认后撤销恢复建议、历史列表计数、分析中只读预览，以及默认界面仅展示有效建议、分析记录筛选与原文引用展开。当前后端完整检查342项通过、17项条件测试跳过；前端构建及7项相关浏览器测试通过。本地服务更新后通过真实API核实12/206/96的分流计数、原图145节点/167边逐项一致，并在实际页面确认默认选中“合并建议（12）”、模型理由及引用可展开。

## 区分文档原文与生成节点属性

用户指出 `517ed11c-89d9-41ec-8fcc-f6762112572b` 的描述未包含“美国商务部工业与安全局（BIS）”。核对发现：左侧模型引用逐字命中了生成节点的 `title`，而该节点的原文只出现“BIS规则”；右侧节点关联的文档原文确实包含全称。旧适配器将原文和生成属性拼入同一个 `context`，因此属性文本也通过了字面引用校验，界面却统一称为“原文依据”，这一证据归属不准确。

现在 GraphRAG 比较与别名扩展的 context 仅使用文档原文，生成名称、描述仍作为检索提示；无原文不调用模型补造依据。在线模型版本更新为 `bank-resolution-v3-source-quotes`，旧的混合上下文缓存不会作为新任务的有效原文判断复用。数据库引用仍核对来源字段，并在页面明确标识来源类型。

读取历史结果时，逐侧对照原始快照定位引用：文档原文提供相邻上下文和分块 ID，仅在属性中出现的引用列出对应字段，无法定位则显示未核实。只有来源校验通过的建议进入确认队列；旧模型结论与已有人工操作保留，未核实引用不能经普通确认接口合并，自动应用也排除相关分组。

在 `91ca7ce7-421f-4692-92d7-4b8add5df134` 原12组建议中，有9组至少一侧只引用了生成属性，重新校验后为3组待确认、206组自动不合并、105组未建议合并。这不是对9组实体判为不同，也不是新的模型运行；需要用真实原文重新分析后才能形成新建议。原始145节点/167关系及人工审计保持不变。后端完整检查346项通过、17项条件测试跳过；前端构建通过，新增回归覆盖生成字段冒充原文、无原文、数据库来源标注、历史建议和确认接口。

## 完整原文查看

“查看原文与引用”按需读取当前候选的不可变输入快照，左右并排展示完整关联原文、模型引用及实际来源，精确高亮原文中的引用。生成的 description 单独标记并折叠；找不到引用时只显示归属说明，不在原文中补造文本。数据库记录显示来源字段，缺失文档原文明确提示。多分块保留分析时保存的顺序和完整拼接文本，并提供全部分块 ID，不猜测缺失的精确块边界。
