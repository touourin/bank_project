# 第二步：本体对齐与图谱生成

链路：选暂存表 → 结构与样例分析 → 本体候选召回 → 字段映射及图模板草稿 → 按需修改/整体采纳 → 全量分批实例化 → 原子发布业务图谱。接入、模型分析与图谱生成是独立动作。

## 模型分析和过程

最多选择 30 张表。MySQL 模式只读取表结构与分布在表内的最多 5 行样例，每个样例值截取 80 字符；全量原值仍在不可变暂存批次。不会先把全表加载到内存，也不会每条数据调用一次模型。

小表在输入预算内通常一次模型调用。超过默认 32 列的宽表先用紧凑字段目录制定整表概览，再按最多 32 列一批、最多 3 批并发解释字段。每批共享同一份整表含义与分组标识，不能自行新增分组；按原列顺序合并并校验每列恰好出现一次。模型只解释表/列的中文含义、实体分组和连接字段，不返回本体节点 ID 或匹配分数。节点完全由 `retrieve` 返回；候选名称和上级关系从本次固定版本的本地快照补充。

每个数据提示最多 48,000 字符，字段批次也按实际输入长度缩小。整表目录过长时只对概览目录做分布抽样，并明确提示人工核对分组；所有字段仍逐批解释，原数据不删减。模型输出因 token 上限截断，或返回字段发生遗漏、重复、越界时，将受影响字段批次二分重试，直到单列；已成功批次不重跑。仍不完整、格式错误或未知分组会报告具体批次与列序号，并取消未完成并发请求。部分批次结果不会当作完整映射交付。模型重试与拆批有界，但字段越多仍会增加请求次数和费用，外部限流或延迟仍可能导致失败。

前端显示已完成批数、已解释字段数和随后执行的 retrieve 阶段；一张表失败会显示具体原因，其余表继续分析，全部失败不会显示“规则已就绪”。目前不支持失败批次断点续跑，重新分析会创建新任务。

检索词优先采用清晰的原始中文表名/字段名，其次采用简短字段注释，缺少这些信息时使用模型解释。避免把“客户名称”改写成长描述而损失精确命中。“数据”“Sheet1”等通用表名使用模型解释的业务检索词，不覆盖为通用名称；模型同时接收来源文件名作为语义上下文。

`POST {BANK_RETRIEVE_BASE_URL}/retrieve` 的请求为 `{"query":"客户名称","expected_revision":"当前本体版本"}`。query 只包含概念或字段含义，绝不主动发送全表数据。每张表、每列和每个实体分组各构造一条查询，相同查询在同一任务/同一版本中复用成功结果；缓存最多 2,048 项，失败结果不缓存。固定请求工作池默认并发 3，每请求总超时 60 秒，部分瞬时 HTTP 故障最多重试一次，响应上限 1 MiB。增加行数不会增加匹配请求数量；宽表和大量异构表仍会增加请求次数。检索每完成 24 项保存一次进度。

自动采用同时要求：返回版本与本地一致、节点在快照中、接口明确选中该候选、`confident=true`、有效分数不低于 `BANK_ALIGNMENT_MIN_CONFIDENCE`（默认 0.75）。分数不是正确概率，不同匹配方式也不保证分数可直接比较。有效的低分/无分数候选进入生成草稿并标注为建议，可整体采纳；无候选、节点越界或版本异常时不补造节点。普通字段检索失败不再阻止整张表，其原值仍作为原始属性保留，候选及错误记录可查看。整表或实体分组至少要有有效对象候选才能生成，否则明确展示排除原因。采纳方案不会把原始低分状态改成高置信度。

启动分析前通过 `/ready?expected_revision=...` 检查服务版本；每次 retrieve 仍绑定同一版本，防止运行中切换。必须配置 `BANK_RETRIEVE_BASE_URL`，不能把“没有调用服务”显示成“已匹配”。本地快照仍负责目录、节点存在性、人工搜索和版本校验。现有运行记录、原候选证据和图谱版本保留。

页面区分历史模型匹配与新 retrieve 匹配。新记录展示每个查询、候选节点、原始得分、匹配方式、接口有把握标记和本地采用状态，支持筛选待处理项和人工修改。快照最高 30 MiB，单表映射最高 2,048 列；模型输入为表结构与少量样例，不会静默丢列。

配置说明：

| 配置 | 用途 |
| --- | --- |
| `BANK_RETRIEVE_BASE_URL` | 本体作用域地址，形如 `http://host:30080/v2/ontologies/<uuid>`，不包含 `/retrieve` |
| `BANK_ONTOLOGY_REVISION` | 固定本体快照版本，必须与接口本体一致 |
| `BANK_RETRIEVE_TIMEOUT_SECONDS` | 单次请求总时限，默认 60 秒 |
| `BANK_RETRIEVE_CONCURRENCY` | 默认 3，允许 1–8 |
| `BANK_ALIGNMENT_MIN_CONFIDENCE` | 匹配分数门槛，默认 0.75，沿用配置名以兼容已有部署 |
| `BANK_ALIGNMENT_BATCH_COLUMNS` | 单批最多字段数，默认 32，允许 1–64；输入过长时自动缩小 |
| `BANK_ALIGNMENT_MODEL_CONCURRENCY` | 字段解释并发上限，默认 3，允许 1–8；与 retrieve 并发分开 |

检索客户端默认直连，不读取系统代理，避免内网本体请求被代理转发。接口的根地址可用 `GET /v2/ontologies` 查看本体列表与 active revision；选择与本地快照一致的版本，不要为了连接成功盲目切换本体。

## 字段映射与图模板

默认操作顺序为“选择数据 → 查看完整匹配方案 → 整体采纳并生成”。选择区只用于新分析，任务区明确列出当前结果所属的数据表；两者不一致时给出提示。普通单实体表使用稳定的按表模板和来源声明的主键，不使用模型单分组建议覆盖身份字段。

“生成方案”直接展示对象类型、来源文件/表、身份字段、属性和关系。完整图模板收进高级配置，保留实体拆分、跨表合并及关系编辑。模型提示多个对象或分组不完整时保存并持续展示 `structure_notes`，无需逐项勾选确认。低分对象建议有明确提示，可以修改，也可以一次性采纳；这不代表模型推断必然正确。

点击“使用默认方案”可切换为按行保留的方案：每张表一个对象定义，每条来源记录独立生成实例，所有原始列按原名保留，不选择业务身份字段、不拆分、不合并、不建立关系。沿用当前单对象的类型选择；多对象方案改用已有的整表候选。缺少有效对象候选的表会明确列出，不随机选择本体节点。重复或空业务编号不会导致记录合并，这也意味着同一客户的多条记录仍是多个实例；需要客户归并时应另行配置可靠身份字段。

默认方案接口仅读取任务结构，不读取全表或再次调用模型/检索。返回可编辑草稿，不创建任务版本、不发布图谱；原始分组建议收进可展开说明，低分提示继续保留。“恢复之前方案”可恢复切换前的草稿，采纳后按原有流程保存新版本。模板 `mode` 区分 `suggested`、`row_records` 和 `custom`；调整默认规则后转为自定义方案，后端校验默认标记与实际规则一致。

生成区区分来源行数、对象类型数和关系规则数，不把它们当作实际实例数量。实际节点数、关系数与来源任务在发布后展示。查看历史任务不会切换当前已发布图谱，页面明确标明两者是否来自同一任务。

字段映射记录每列含义及对应概念；图模板进一步定义字段属于哪个实体/事件。例如流水一行可以拆成客户、账户、交易，姓名归客户，账号归账户，金额和日期归交易。字段分组由模型解释，分组概念由 retrieve 匹配；有效分组不再依赖整表名称命中；单对象仍使用来源声明的主键和原始属性名。分组存在明确主对象（检索词与整表一致）时，未分组字段附于该对象作为原始属性并说明；其余不完整分组保留整表草稿及原因，避免静默丢字段或参与方。系统可能给出不完整草稿，前端允许增删分组、修改本体概念、字段归属与属性名称、身份标识和关系。

- **身份范围＋本体概念＋标识字段值**共同决定实例身份。多张表补充同一客户时，需人为设定相同身份范围、概念及同义标识字段；复合键按字段顺序逐字比较，保留前导零，不自动忽略大小写或空格。不能用姓名作为可靠唯一身份。
- 没有可靠身份字段时，每条来源记录独立成实例。选定身份字段但记录缺值时停止发布并报告位置，防止所有空编号合为一个人。
- 同身份可以合并不同属性。同名属性值冲突会拒绝发布，不采用任意一行覆盖；历史余额、状态等变化值应建成带时间的事件/快照，或明确取值规则后再处理。
- 关系必须有来源依据：同一行的两个角色，或跨表精确连接字段。跨表目标连接值要求唯一；非空连接值找不到目标会停止模板发布。NULL/空串不是关联键。多对多关系应使用明确的关联表，不自动笛卡尔展开。
- 本体关系帮助理解结构；本体上存在 A→B→C 路径不能证明实例 A 与 C 发生交易。仅凭本体连线不会创建业务事实。
- 未选入模板的原始列不会丢失，仍在暂存库。实例由字段归属决定，不是把每个年龄数值都建成一个本体类型节点。

点击“采纳方案并生成”，提交当前完整草稿，后端校验后在同一事务中保存新方案版本并领取生成任务。不能领取任务时不留下孤立版本，前端保留修改供重试。也可选择“仅保存方案”，暂不生成。原始候选、得分、历史方案与已发布图谱保留；不自动重写旧任务，需要重新分析以获取新的完整建议。人工修改和整体采纳都使用原分析一致的本体 SHA256/revision，不允许混用版本。当前是精确业务键合并，不包含模糊实体消歧、本体目录编辑或报告生成。

SQLite 小数据兼容模式和历史任务仍使用原按行构图路径，不会被静默改成新身份合并规则。

## 全量图谱浏览

前端默认展示“本体分类网络”：分类节点的数量来自整个已发布版本的聚合统计，点击分类可浏览该类的全部实例。分类归属点线由前端根据实例的 `concept_id` 绘制，不写入 Neo4j，也不计入业务关联数量。“业务关系”视图只展示已保存的关系，支持从实例详情继续查看该实例的关联对象，包括原批次外的对象。

实例按不可变版本和节点 ID 游标分页，每批 50、100 或 200 个，显示当前范围和总数；切换批次替换画布内容，避免浏览过程中无限积累节点。全量搜索由服务端对当前版本内的实例名称、编号和已写入字段值执行字面子串匹配，可叠加分类筛选，不局限于已显示的节点。当前搜索为有超时限制的属性扫描，不属于全文索引；数据规模增大后可独立替换检索适配实现。未完成的查询显示错误，不把超时当作“没有记录”。

概览不返回完整实例属性；分页接口只返回实例摘要，最多显示当前范围内 500 条业务关系，超出时明确提示。点击节点后按该版本读取单条实例的全部已写入属性，保留精确数字字符串、空字符串与已有 NULL；历史模板编译省略的空值不会伪造为已存储属性。详情显示来源表、源行号和本体节点 ID。展示名称优先使用客户/企业名称等明确字段，事件使用事件码与日期；不再把内部表 ID 当作名称，也不使用法人姓名冒充企业名称。

图形使用按需加载的 Cytoscape.js 模块，支持拖动、缩放、展开画布、显示名称和导出当前画面。浏览、搜索和分类展示均为只读操作，不触发重新分析、修改映射或发布新图谱。发布新版本后重新读取概览才切换版本，旧分页与详情始终绑定原版本，避免跨版本串数据。

## 大数据执行与存储

`staging/keys.py` 在 MySQL 建关联索引，使用摘要定位并再次比较完整键值，避免摘要碰撞和数据库排序规则误配。`staging/compile.py` 用磁盘表分批编译已确认模板，保存来源行与实例对应关系，检查属性冲突并去重。Neo4j 每批最多 200 条/约 2 MiB，全部节点和关系通过计数及任务所有权检查才切换当前版本。

单行/合并后单实例都有 2 MiB 上限；分页、批大小、并发和数据库空间仍决定容量。失败的 MySQL 临时编译表由 worker 分批清理；运行中的编译维护心跳，长时间失联的残留可回收。输入不可变，重跑不会修改原批次。失败的 Neo4j 隔离版本和历史版本保留，尚无自动保留期清理。

分析库 `BANK_DATA_DIR/alignment/runs.sqlite3` 保存小体量过程、模板、样例及租约，新任务不复制整表。运行时按引用分批读取 MySQL。隐藏第一步批次不会破坏历史分析。分析/建图单实例执行，租约每 10 秒续期，60 秒失效；失联任务标为失败，不假装持续运行。

Neo4j 与运行记录不是分布式事务：图谱发布后运行状态落盘前若进程退出，任务可能显示中断，实际已发布版本以 Neo4j 指针为准。不能清空运行库序号并复用同一业务图状态。Kubernetes 多副本前仍需迁移分析运行库/协调方式，当前不是分布式计算平台。

## 接口和模块

| 路径 | 职责 |
| --- | --- |
| `alignment/sources.py` | 获取不可变结构、样例和全量数据引用 |
| `catalog.py` / `model_client.py` / `planning.py` | 本体目录、模型传输及不含节点 ID 的语义解释契约 |
| `interpretation.py` | 统一概览、字段分批、并发边界与完整合并 |
| `retrieval.py` / `matching.py` | retrieve 传输、缓存与并发边界；独立的节点采用决策 |
| `analyzer.py` / `tracing.py` | 按表分析、过程记录 |
| `editing.py` / `templates.py` | 人工映射版本、图模板结构校验 |
| `presets.py` | 基于已有候选生成按行保留的默认方案 |
| `staging/keys.py` / `compile.py` | 磁盘关联与实例编译 |
| `alignment/store.py` / `service.py` | 小体量运行状态、租约和编排 |
| `alignment/graph.py` | Neo4j 分批写入、隔离版本发布 |
| `alignment/browsing.py` / `display.py` | 全量分类统计、游标分页、搜索与实例显示名称 |

接口前缀 `/api/v1/alignment`：

- `GET /config`：非敏感配置。
- `POST /runs`：`{"tables":[{"batch_id":"UUID","table_id":"UUID"}]}`，返回 202。
- `GET /runs`、`GET /runs/{id}`：最近任务及详细过程。
- `GET /runs/{id}/concepts?q=名称或ID`：原本体版本最多 50 个候选。
- `POST /runs/{id}/mapping`：修改表或字段概念及依据，另存 201。
- `POST /runs/{id}/template/default`：提交当前图模板，返回默认方案草稿，不持久化、不生成图谱。
- `POST /runs/{id}/template`：完整模板，校验并另存确认版本 201。
- `POST /runs/{id}/graph`：可提交完整图模板，原子地另存采纳版本并启动生成，返回新任务 202；无请求体时兼容生成已确认版本。
- `GET /graph`：当前已发布版本和最多 50 节点/100 边预览。
- `GET /graph/overview`：当前已发布版本及全量分类计数，供新版前端使用。
- `GET /graph/{version}/nodes?concept=&q=&after=&limit=100&focus=`：版本固定的实例分页；`focus` 按真实业务关系查询指定实例的关联对象，中心实例单独返回，不占分页条数。
- `GET /graph/{version}/nodes/{node_id}`：指定版本的一条实例及全部已写入属性。

沿用 Bearer 与 Origin 防护；普通 JSON 请求上限 64 KiB，默认方案预览、模板保存与携带模板的生成请求 1 MiB。字段名保存在 JSON 及映射中，不拼接 Cypher。错误不返回数据库凭据或模型原始响应。
