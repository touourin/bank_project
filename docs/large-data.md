# 大数据改造验证

2026-09-19 在当前本机、Docker MySQL 和独立验证 Neo4j 中实测。原有业务图谱未用于负载测试。

| 项目 | 实测 |
| --- | --- |
| 输入 | `examples/mock/交易流水.xlsx`，278,832,028 字节，约 265.91 MiB |
| 数据规模 | 539,534 行 × 103 列；工作簿解压约 4.25 GiB |
| 流式解析到 MySQL | 282.95 秒，解析进程 RSS 峰值 61,784,064 字节（58.92 MiB） |
| 模板编译及 Neo4j 发布 | 606.86 秒，构图进程 RSS 峰值 82,345,984 字节（78.53 MiB） |
| 测试图 | 542,554 实例，541,554 关系 |

负载模板拆分客户、账户、交易：客户键 `cust_ind`，账户键 `accno`，交易复合键 `accno + acc_dtl_sn`，客户到账户、账户到交易使用同一条流水的证据。该模板采用测试概念，仅用于检验容量和确定性执行，不能把测试概念视作已确认的银行本体映射。完整流水没有逐行调用模型。

RSS 是对应 Python 进程的峰值，不包含 MySQL、Neo4j、Docker 虚拟机、OS 文件缓存；耗时依赖本机配置和当时负载。测量不能承诺任意数据量、任意宽度或多人并发均可支持。接入限额、单行限制、队列与上传并发仍保留；硬盘、数据库索引和图版本保留需监控。

故障验证覆盖：保留前导零/金额精度/NULL、编码及跨行 CSV、XLSX 共享字符串与公式拒绝、越界请求清理、取消/重试及旧处理权失效、键摘要碰撞精确比较、同身份跨表属性合并、属性冲突拒绝发布、Neo4j 发布失败保持旧版本。

后续更大规模可按实测增加 worker/数据库资源，但目前分析协调仍为单 API 的 SQLite 租约。多副本、文件断点续传、图生成断点续跑、CDC 增量同步和自动保留期清理尚未实现。
