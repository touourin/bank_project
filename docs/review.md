# 导入与转换模块检查记录

检查日期：2026-09-18。范围：通用导入、转换、接口、持久化、映射、模型适配和 Docker 配置。

## 已确认并修复的问题

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| Excel/MySQL 将日期时间格式化为 YYYYMMDD | 时间戳丢失时分秒，通用来源被套用业务格式 | 改为保留 ISO 日期时间和时长；测试小数秒、负时长、超过 24 小时和两种 Excel 日期存储 |
| Excel 在展开单元格后才检查行列上限 | 稀疏异常坐标可能先大量分配内存；重复坐标可能覆盖数据 | 先检查原始 XML 的范围、顺序、重复及行列一致性；测试确认异常输入不进入单元格展开 |
| 模型返回空对象或缺字段可视为成功 | 不完整结果被误认为没有事实 | 三个结果数组必填；明确空数组仍有效；畸形响应统一为可识别错误 |
| 模型响应大小在解压后检查 | 压缩响应可能先占用过多内存 | 请求 identity 编码并拒绝压缩响应；测试确认不读取压缩内容 |
| 导入/转换请求没有专门的并发上限 | 多批大文件和模型任务同时占用资源 | 每进程默认最多 2 个请求；繁忙时在读取上传前返回 503，保留健康和查询接口 |
| 同一对象的来源证据反复做列表查重 | 大批重复对象使转换耗时平方增长 | 增加集合索引，保留证据顺序；用同一公司参与 1,000 次独立事件验证证据和事件均不丢失 |

## 全局结构

- ingestion 与 extraction 分开调用，通过持久化契约交接；两者不直接依赖基础设施实现。
- 客户标签和旅程只在映射配置中出现，通用代码仍适用于其他业务表。
- Excel 的底层检查和来源标量序列化独立成小模块；HTTP 层负责鉴权、请求限制和并发准入。
- 对象、事件、关系分别保留标识与原始证据；冲突属性、重复业务主键、无效引用会失败，不默默覆盖。
- 路径访问限制、只读数据库白名单、原子落盘、批次锁、失败重试、模型原文证据检查均有回归测试。

## 仍需遵守的运行边界

- 当前文件持久化适合单实例配持久卷；多副本需要共享状态和分布式任务控制。并发上限按进程计算。
- 默认服务供可信开发团队通过本机端口使用。对外开放应配置鉴权；统一 API token 不提供用户级、数据集级权限。
- PDF/Office 解析仍在服务进程内执行，有大小与并发限制，未提供独立沙箱进程或硬性 CPU/内存隔离。
- 后续已完成本地 Docker MySQL 实际建表、落库及 API 读取转换联调，详见 database.md；银行真实数据源与真实模型服务仍未联调。模型原文引用校验不能代替语义准确率评估或人工复核。
- 历史导入快照不自动重写。解析修复后使用新 batch_id 重新导入；旧结果仍可读取。
